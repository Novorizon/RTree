# 3D 场景查询树规划

本文件保留 RTree 完成后的扩展路线与验收依据。阶段 0–3 的 CPU 索引已落地：
共同几何/查询接口、RTree 适配、动态 AABB BVH、静态/三角形 SAH BVH、loose
octree 和点 KD-tree，并验证了两层场景组合。API 与语义见
[SpatialQueries](SpatialQueries.md)，性能见
[SpatialPerformance](../validation/SpatialPerformance/README.md)。
现有 RTree 仍是比较基线，保留其公开 API；LBVH/HLBVH、GPU、BSP/SVO 等
属于后续按需求推进的方向，不预设某一种树或后端普遍更快。

## 当前基线

现有实现已提供连续托管数组、内联 double AABB、R* 风格分裂、STR 批量构建、
复用结果缓冲区、查询统计与同树并发读。查询包括 AABB 相交、包含，以及
距离上限内的全部并列最近项；现有 `Nearest` 不等于 kNN。

18 组回归和 168 个随机场景已验证；性能数据覆盖 10k、50k 及 1M 条目。
百万级报告每类只有 32 条查询、3 轮批次，不能用作单次查询的 P99。
后续比较应复用数据生成器和独立暴力 oracle，另加足量的逐查询采样。
原 .NET Framework 4.5 项目与 .NET 8 验证环境的兼容边界仍需明确。

## 结构与适用场景

**AABB tree 是使用 AABB 包围体的 BVH。** 动态 AABB BVH、静态 SAH BVH 和
LBVH 是更新或构建策略的区别，不是互斥的大类。BVH 还可以使用球、OBB、
k-DOP 等包围体；只有 AABB 的假阳性或方向适应性成为实际瓶颈时再评估它们。

| 结构 | 优先应用 | 更新与构建方式 | 主要取舍 |
| --- | --- | --- | --- |
| 当前 RTree / R* 风格 | 任意大小对象、范围选择、包含查询、GIS、编辑器 | 增删、STR 批量构建、重打包 | 包围盒重叠影响裁剪；不把完整 R* 强制重插当作默认必需功能 |
| 动态 AABB BVH | 移动物体、物理 broad phase、交互场景、编辑器 | fat bounds、Move、refit、移除重插、局部旋转 | 余量减少结构更新，但增加候选与窄相成本 |
| 静态 SAH BVH | 静态网格、三角形射线、碰撞候选 | 分桶 SAH 构建；变形 refit，质量下降后重建 | 建树更贵，优先减少图元测试 |
| LBVH / HLBVH | 大批量重建、并行建树、后续 GPU 场景 | Morton 编码排序与层次构建；混合 SAH | 建树吞吐与查询质量分别比较；CPU/GPU 各自计量 |
| Octree / loose octree | 有界世界、区域/视锥查询、流式场景管理 | 空间单元细分、松散单元、根扩展 | 需规定跨单元对象、大对象归属与深度限制 |
| 点 KD-tree | 点云、点最近邻、kNN、半径查询 | 静态或批量重建；动态增量另行测量 | 擅长点集合；与射线空间切分 KD-tree 分开设计 |
| 射线 KD-tree | 静态几何的空间切分与射线遍历 | 切分空间；跨平面图元可能复制 | 与 BVH 相比需计入复制、内存和构建成本，后置 |
| BSP | 静态平面分区、CSG、特定可见性问题 | 图元切分、平面分类 | 数值鲁棒性和维护成本较高，按独立需求推进 |
| Sparse voxel / SVO | 占据场、体素遍历、体积数据 | 量化、稀疏体素构建与更新 | 有分辨率语义，不能直接替代任意对象索引 |

典型组合是两层结构：场景对象用动态 AABB BVH，网格内部用静态 SAH BVH。
对象变换只更新场景层代理，网格图元结构独立复用；实例、射线参数和命中信息
在两个坐标空间之间正确转换，尤其不能在非均匀缩放后混淆距离和射线参数。

## 统一契约

先通过适配器接入现有 RTree，避免为了统一接口而破坏已有调用。按能力拆分
包围盒查询、动态更新、射线和点最近邻接口，不要求所有结构实现全部操作。

| 能力 | 规划操作 | 必须明确的语义 |
| --- | --- | --- |
| 包围盒索引 | AABB 相交/包含、球、视锥查询 | 接触边界是否命中；返回真实 bounds 还是保守代理候选 |
| 动态代理 | Insert、Move、Remove | 使用槽位＋generation 句柄；失效句柄拒绝，句柄不等于节点编号 |
| 射线候选 | RayAny、RayClosest、RayAll | `tMin/tMax`、零方向分量、并列、排序、起点在内部的处理 |
| 点最近邻 | Nearest、KNearest、Radius | 点到点/盒/图元的距离；k 个还是包含第 k 距离的全部并列项 |
| broad phase | QueryPairs、更新 pair cache | 无序 pair 唯一、自配对排除、过滤层、保守候选的定义 |
| 运动候选 | SweptBounds、运动范围查询 | 只保证候选无漏报，不承诺连续碰撞检测或精确 TOI |

共享几何建议采用值类型 `Bounds3`、`Ray3`、`Sphere3`、`Frustum3` 与明确的
数值规则。先保留 double 基线，float 版本单独比较精度、内存和性能，
避免默默降低现有坐标精度。公有类型与目前内部 `Aabb` 的迁移通过适配器完成。

payload 留在托管槽位中，树节点保存整数句柄。新动态句柄包含 generation，
移除再复用槽位后旧句柄必须失效。每次活动查询独占一个 context 和调用方
结果缓冲，支持可选 `NodesVisited`、`BoundsTests`、`PrimitiveTests`、
`ResultCount` 等统计；复用 API 与分配结果的便利 API 分别计量。

## 候选查询与精确命中

树只了解包围体时，球、视锥、射线和 AABB 查询产生包围体候选。精确三角形、
曲面或其他形状的相交由图元适配器执行。应分别记录包围体测试与图元测试。

`RayClosest` 若承诺精确图元命中，必须用图元的真实交点更新距离上限；
最近的包围盒不能直接作为最近图元的答案。遍历可以使用包围盒下界裁剪，
但不能因此省略需要的窄相验证。

动态树应分别保存真实 bounds 和 fat bounds。返回保守代理候选的接口允许
假阳性；需要与 RTree 精确 bounds 查询公平比较时，适配器应追加真实 bounds
过滤，并把这部分成本计入同一个查询。候选性能与精确 bounds 性能分开报告。

线性平移的 swept bounds 可使用端点 AABB 并集。旋转、骨骼变形和非线性轨迹
不能只用端点并集；需要覆盖完整运动的保守边界。swept broad phase 与精确
连续碰撞检测是两个独立阶段。

## 更新和并发

动态 AABB BVH 的 `Move` 在新真实 bounds 仍位于 fat bounds 内时可跳过重插；
越界时重插，并通过 refit、旋转或质量阈值控制退化。余量策略应同时测试
固定扩张与速度预测，记录重插次数、候选数量和总 broad+narrow phase 成本。

如果采用“本帧移动代理＋pair cache”，缓存中仍可能接触的候选不能每帧清空。
物体可能在同一 fat bounds 内开始真实相交而未触发重插；候选 pair 必须保留
并进入后续窄相。删除、过滤变化和不再可能接触的 pair 应有明确失效规则。

静态 BVH 的 refit 只修正边界，不保证原有 SAH 质量。通过树高、面积比、
重叠、节点访问和图元测试数判断是否重建，不使用未经测量的固定通用阈值。

第一阶段沿用可验证的读写锁。静态树可进一步采用后台构建、完成后原子发布的
不可变快照；必须在旧读者结束后回收旧缓冲。快照保护索引结构与边界，
不会自动冻结用户 payload。读吞吐、混合读写延迟和重建阻塞分别测试。

Octree 方案需在实现前确定：根是否自动扩展、最大深度、坐标归属边界、
跨单元对象是否只存祖先节点、大对象上浮规则，以及采用重复存储时的去重。
Loose octree 同样需要测量松散系数与更新/候选数量之间的关系。

## 公共验证与性能矩阵

数据生成器可以共享，正确性 oracle 独立实现。不同结构先统一查询语义、
输入、命中量、过滤与输出物化方式，再比较性能。

| 维度 | 必测内容 |
| --- | --- |
| 规模 | 100k、1M；更大规模按实际内存预算增加 |
| 分布 | 均匀、聚簇、平面、线状、混合尺寸、长薄对象、全重叠、稀疏世界 |
| 动态性 | 静止、不同移动比例/距离、跨节点移动、突变、传送、批量销毁重建 |
| 查询 | AABB、sphere、ray any/closest/all、frustum、kNN、radius、pairs、swept 候选 |
| 数值与句柄 | 边界接触、退化几何、极大/极小坐标、零方向、失效句柄、槽位复用 |
| 构建和维护 | 增量/批量构建、Move、Remove、refit、Rebuild、重建峰值内存 |
| 查询成本 | 单线程时间、分配量、保留内存、节点/图元测试数、候选与实际命中量 |
| 延迟和并发 | 足量逐查询 p50/p95/p99；并发读吞吐、混合写入和重建时尾延迟 |

验收以无漏报为底线：精确 bounds 查询与暴力扫描一致；保守 broad phase
返回 oracle 的超集，并报告假阳性及 pair 数量；精确图元射线与直接图元遍历
一致。热查询零分配的前提是输入、结果和 context 容量已准备好，构建与扩容
分配另计。GPU 还需分别记录上传、构建、查询和下载成本。

性能采用 Release、固定种子、预热、足够轮数、相同运行时和顺序执行的 A/B。
现有“轮级批均值分位数”保留为批次指标，新方案另采单次查询尾延迟，
不能把两种分位数混用。每个结果记录环境、参数、版本和校验和。

## 实施顺序与阶段验收

| 阶段 | 交付物 | 完成条件 |
| --- | --- | --- |
| 0：公共基础 | 值几何契约、句柄、能力接口、RTree 适配器、共享基准/oracle | 现有 RTree 测试保持通过；旧 API 不变；比较路径语义一致 |
| 1：动态 AABB BVH | 连续池、fat bounds、Move/Remove、refit/旋转、pair 查询/缓存 | 随机移动/销毁无漏报；句柄复用正确；与 RTree 比较范围查询和更新总成本 |
| 2：静态 SAH BVH | 分桶 SAH、三角形适配、射线 any/closest/all、refit/rebuild | 射线与图元暴力遍历一致；记录建树、图元测试数及变形后的质量 |
| 3：场景专项 | 按真实需求加入 loose octree、点 KD-tree；验证两层实例结构 | octree 跨单元/根扩展正确；点 kNN/radius 与暴力扫描一致；场景数据有比较收益 |
| 4：构建吞吐与后端 | 有证据后实现 LBVH/HLBVH、GPU 或非托管存储 | 连同数据传输和维护成本形成可复现收益；相同 oracle 与数值契约通过 |
| 独立需求 | BSP、SVO、OBB/k-DOP 等 | 先有 CSG、体素或方向性包围体需求，再制定专项验收 |

建议先实施阶段 0 和动态 AABB BVH，再做静态 SAH BVH。它们分别覆盖动态
场景和静态网格这两类主要需求。其他结构按实际查询与更新负载加入，
不同时铺开所有实现。非托管内存是可选后端；只有分析证明 GC、布局、对齐或
互操作成为主要瓶颈后再评估，不作为树算法的替代优化。
